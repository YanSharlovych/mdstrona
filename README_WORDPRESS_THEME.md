# ALUTECO WordPress block theme

This repository contains the original static ALUTECO site and its complete
WordPress implementation. The WordPress version is a native block theme built
with core Gutenberg blocks and patterns. It does not require ACF, a page
builder, custom React blocks, or any frontend framework.

## What is included

- Separate editable pages for Home, Home Systems, Marine Doors, About Us,
  Contact, and News.
- Site Editor templates for the header, footer, pages, posts, archives, search,
  and 404 responses.
- Global design tokens and editor styles in `theme.json`.
- Core block patterns for the complete page compositions and reusable sections.
- Dynamic WordPress posts with categories, tags, featured images, search,
  archives, pagination, and single-post navigation.
- A server-side contact form with nonce validation, sanitization, validation,
  honeypot and timing checks, and Mailpit delivery in Docker.
- Idempotent WP-CLI setup and demo-content seeding.
- Persistent MariaDB and WordPress file volumes.
- HTTP and Playwright browser checks.

## Architecture

The theme lives at:

```text
wp-content/themes/aluteco/
```

Important directories:

```text
assets/       Theme images, logos, and JavaScript
inc/          Contact form and idempotent content bootstrap
parts/        Site Editor header and footer template parts
patterns/     Full-page and reusable Gutenberg patterns
templates/    Front page, pages, posts, archives, search, and 404 templates
```

The original `*.html`, `styles.css`, `script.js`, and root `assets/` files are
kept as the approved static reference. WordPress serves files from the theme
directory.

## Local setup

Requirements:

- Docker Desktop with Docker Compose
- Node.js 20 or newer only when running Playwright tests

Create a local environment file:

```powershell
Copy-Item .env.example .env
```

The defaults are intended only for local development. Change the database and
administrator passwords before using the stack outside a private computer.

Start the complete environment:

```powershell
docker compose up -d
```

The first run installs WordPress, activates the theme, seeds content, imports
media, sets the homepage and News page, and configures permalinks.

Local URLs:

- Site: `http://localhost:8080`
- WordPress admin: `http://localhost:8080/wp-admin/`
- Mailpit: `http://localhost:8025`

Default local administrator credentials:

```text
Username: aluteco_admin
Password: local-only-change-me
```

Run setup again after a clean database or after adding seed definitions:

```powershell
docker compose run --rm wpcli
```

The bootstrap is idempotent. Existing page and post content is not overwritten.
Missing seeded media relationships are restored when possible.

Activate the theme manually when importing it into another WordPress
installation:

```powershell
docker compose run --rm --entrypoint wp wpcli theme activate aluteco
```

The same action is available under `Appearance > Themes` in WordPress admin.

Stop the containers without deleting content:

```powershell
docker compose down
```

Delete all local WordPress and database data only when a completely clean
installation is required:

```powershell
docker compose down -v
docker compose up -d
```

## Editing content

### Pages

1. Open `Pages` in WordPress admin.
2. Choose Home, Home Systems, Marine Doors, About Us, Contact, or News.
3. Edit text, images, links, buttons, and core block settings in Gutenberg.
4. Use List View to select nested Cover, Group, Columns, or Query blocks.
5. Publish or update the page.

The News page itself is the WordPress posts page. Its listing layout is managed
by the `Home` template in the Site Editor.

### Header, footer, and navigation

1. Open `Appearance > Editor`.
2. Use `Navigation` to edit menu labels, links, and order.
3. Use `Design > Patterns > Manage all my patterns` and open Template Parts to
   edit the header or footer.
4. Use `Styles` to adjust global colors, typography, spacing, and block styles.
5. Replace the Site Logo through the Site Logo block.

The mobile navigation is generated by the core Navigation block. The theme adds
visual styling and small interaction enhancements without replacing WordPress
navigation behavior.

### News

Create articles under `Posts > Add New` and provide:

- title;
- article content;
- excerpt;
- featured image with meaningful alternative text;
- one or more categories;
- optional tags.

The News page, category and tag archives, search results, and pagination update
automatically. The seeded content uses six posts per listing page so pagination
can be reviewed immediately.

### Replacing images

For normal page content, select the Image or Cover block and choose `Replace`.
Keep the image focal point and alternative text up to date.

Theme-owned fallback assets are in:

```text
wp-content/themes/aluteco/assets/
```

If a file is replaced directly in that directory, preserve its filename and
dimensions or update the related pattern and content bootstrap reference.

### Changing icons

Icons in sections such as `How we work` use an editable Gutenberg container.
Open List View, select the icon Group inside the relevant card, and insert an
Icon or Image block into it. Choose the new icon or use `Replace` on an existing
block, then update the page. The theme uses its original SVG only when that
container is empty, so saved Gutenberg icons are never overwritten on the
frontend.

### Using ALUTECO patterns

1. Edit a page or create a new page in Gutenberg.
2. Open the block inserter and choose `Patterns`.
3. Select `ALUTECO pages` for a complete page composition or `ALUTECO
   sections` for a reusable section.
4. Insert the pattern, then edit its text, images, links, and buttons as normal
   core blocks.

Patterns are starting layouts. Once inserted, their blocks belong to that page
and can be edited independently.

## Contact form and email

The contact page uses the `[aluteco_contact_form]` shortcode. Submission is
processed by WordPress and includes:

- a WordPress nonce;
- a hidden honeypot;
- minimum submission time;
- server-side sanitization and validation;
- safe redirect statuses;
- `wp_mail()` delivery with a sanitized Reply-To header.

In Docker, email is sent to Mailpit at `mailpit:1025`. Mailpit captures messages
locally and never sends them to real recipients.

Production must provide a real SMTP solution. Configure it at the hosting level
or with a narrowly scoped SMTP plugin, and test delivery before launch. Remove
or replace the Docker-only `ALUTECO_SMTP_HOST` and `ALUTECO_SMTP_PORT`
environment values in the production stack.

## Tests

Run quick HTTP and WordPress REST smoke checks:

```powershell
npm run test:smoke
```

Install the browser-test dependency once:

```powershell
npm install
npx playwright install chromium
```

Run the Playwright suite:

```powershell
npm test
```

The browser suite checks:

- all public routes and a representative single post;
- HTTP success, missing assets, console errors, and horizontal overflow;
- one `h1`, heading order, unique IDs, labels, and image `alt` attributes;
- keyboard skip link and mobile navigation;
- contact form labels and security fields;
- dynamic news and pagination;
- Gutenberg and Site Editor loading without block warnings.

When custom admin credentials are used, expose them to the test process:

```powershell
$env:WP_ADMIN_USER = "your-admin-user"
$env:WP_ADMIN_PASSWORD = "your-admin-password"
npm test
```

Additional useful checks:

```powershell
docker compose config
docker compose ps
docker compose logs wordpress
docker compose run --rm --entrypoint wp wpcli theme list
docker compose run --rm --entrypoint wp wpcli plugin list
```

Follow runtime logs:

```powershell
docker compose logs -f wordpress db mailpit
```

WordPress writes local debug messages to
`wp-content/debug.log` inside the WordPress volume. The file is not exposed to
visitors and is ignored by Git. In production, disable `WP_DEBUG` and
`WP_DEBUG_LOG`.

## Technical decisions and limitations

- Core Gutenberg blocks, patterns, templates, and template parts keep the theme
  compatible with WordPress updates and avoid a page-builder dependency.
- Existing visual class names are preserved in the theme stylesheet to retain
  the approved desktop and mobile design.
- The setup script adds missing demo content and repairs missing seed metadata,
  but intentionally does not overwrite existing page or article content.
- `ENG / PL` remains a visual navigation item because no translated content or
  multilingual workflow was supplied. A production language switch requires
  translated pages and a multilingual strategy.
- Mailpit is for local testing only. Production email requires a real SMTP
  service.
- The included legal pages are clearly marked editable placeholders and require
  review by the client's legal adviser before launch.
- Google Fonts are loaded from Google on the frontend. They can be self-hosted
  if the production privacy policy or offline requirements demand it.

## Backups and deployment

Before deployment, back up both the database and `wp-content/uploads`.
The Docker named volumes are convenient local persistence, not a production
backup strategy.

A production handoff should include:

1. the `aluteco` theme directory;
2. a WordPress database export;
3. the uploads directory;
4. environment-specific WordPress and database credentials;
5. SMTP settings;
6. the final site URL and HTTPS configuration.

After changing domains, use a serialization-aware WordPress search-replace
operation, then resave permalinks and clear caches. Do not perform a raw SQL
string replacement on serialized WordPress data.

## Security notes

- Local credentials in `.env.example` are deliberately non-production values.
- `.env`, uploads, debug logs, database exports, and test artifacts are ignored
  by Git.
- Keep WordPress core and any production plugins updated.
- Use HTTPS, strong unique passwords, least-privilege accounts, and regular
  off-site backups in production.
- Disable debug mode on production.
